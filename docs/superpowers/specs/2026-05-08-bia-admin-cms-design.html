articles table (the only complex new table)

create table articles (
  id              uuid primary key default gen_random_uuid(),
  slug            text not null unique,                -- /blog/[slug] on uscbia.com
  title           text not null,
  language        text not null check (language in ('cn','en')),
  cover_image_url text,
  tags            text[] default '{}',
  author_id       uuid not null references admin_users(id),

  html_raw_path   text not null,                       -- private storage
  html_clean      text not null,                       -- sanitized HTML rendered to readers
  asset_paths     text[] default '{}',
  word_count      int,

  status          text not null default 'draft'
                  check (status in ('draft','in_review','published','unpublished')),
  submitted_at    timestamptz,  submitted_by   uuid references admin_users(id),
  published_at    timestamptz,  published_by   uuid references admin_users(id),
  unpublished_at  timestamptz,  unpublished_by uuid references admin_users(id),

  created_at      timestamptz default now(),
  updated_at      timestamptz default now()
);

create index articles_status_lang_idx on articles (status, language, published_at desc);
create unique index articles_slug_pub_idx on articles (slug) where status = 'published';
05

Blog flow — the wedge

Drop any HTML in the admin, get a published blog post on uscbia.com. The most engineering-heavy piece in this spec.

Naming

  • DB table: articles (clean, generic)
  • Admin path: /admin/blog, /admin/blog/new, /admin/blog/[id]
  • Public path: /blog, /blog/[slug] on uscbia.com
  • UI label: "Blog" everywhere visitors and editors see it
  • Landing-page section: "Latest Dispatches" / "最新动态" stays as the section heading; the three placeholder cards get replaced by real top-3 published posts

The normalize pipeline (packages/bia-shared/html-sanitize.ts)

One function, idempotent, server-side. Transactional with the article insert.

┌──────────────┐ upload input │ upload input │ .html · .zip · pasted clipboard text └──────┬───────┘ ▼ ┌──────────────┐ unzip if needed → temp workspace │ 01 unzip │ └──────┬───────┘ ▼ ┌──────────────┐ parse5 → DOM tree, no browser │ 02 parse │ └──────┬───────┘ ▼ ┌──────────────┐ drop <o:p>, <style>, MS Word junk, deprecated tags │ 03 strip │ └──────┬───────┘ ▼ ┌──────────────┐ whitelist tags (h1-h4, p, ul/ol/li, blockquote, pre, code, │ 04 whitelist │ a, em/strong, img, figure, table…); unwrap others └──────┬───────┘ ▼ ┌──────────────┐ whitelist attrs (href, src, alt, title, colspan, rowspan) │ 05 attrs │ strip all style, class, id, on* └──────┬───────┘ ▼ ┌──────────────┐ base64 → upload, rewrite src │ 06 images │ ./local.png (zip) → match sibling → upload, rewrite └──────┬───────┘ https://… → leave (v1.5 rehost flag) ▼ ┌──────────────┐ DOMPurify defense-in-depth pass │ 07 sanitize │ └──────┬───────┘ ▼ ┌──────────────┐ title from first <h1> · cover from first <img> │ 08 metadata │ word_count from text └──────┬───────┘ ▼ ┌──────────────┐ slug from title · pinyin transliterate for CN │ 09 slug │ -2, -3 suffix on collision └──────┬───────┘ ▼ ┌──────────────┐ { html_clean, title, cover_image_url, asset_paths, word_count } │ 10 output │ └──────────────┘

Sponsors

Two new tables. CRUD + event attachment. Logos surface only on attached events.

create table sponsors (
  id            uuid primary key default gen_random_uuid(),
  name          text not null,
  logo_url      text not null,
  website_url   text,
  tier          text not null check (tier in ('event','recruiting','local','payment')),
  display_order int default 0,
  is_active     boolean default true,
  created_at    timestamptz default now(),
  updated_at    timestamptz default now()
);

create table event_sponsors (
  event_id   uuid references events(id) on delete cascade,
  sponsor_id uuid references sponsors(id) on delete cascade,
  primary key (event_id, sponsor_id)
);
  • /admin/sponsors — table grouped by tier; drag-to-reorder updates display_order.
  • /admin/sponsors/[id] — form + sidebar showing attached events.
  • Storage: public bucket sponsor-logos/{sponsor_id}/{filename}.
  • uscbia.com event cards render attached sponsor logos.

15

Risks & mitigations

As strategic CTO, the risks I'm watching.

Risk 1 — Shipping ops disruption during migration

Officers use uscbia.com/admin/shipping daily. A bad cutover = broken ops, frustrated officers, lost packages. Mitigation: phased per-section rollout, parity smoke checklist, both apps run in parallel through Phases 2–3, 301 redirects during Phase 4 so muscle memory still works.

Risk 2 — Auth model drift (isAdmin → roles)

uscbia.com's admin uses useAuth().isAdmin from a single boolean. New admin uses 3-tier roles. Officers seeded as super_admin get the same access; but if anyone needs editor-only access mid-migration, that user can't log into the old admin (still requires isAdmin). Mitigation: migrate everyone as super_admin first; demote to editor/viewer only after Phase 5 (full cutover).

Risk 3 — Two admin URLs during Phases 2–3
